# Website V2 Content Authority Standard

## Purpose

This standard controls which evidence may authorise public Website V2 content.
It is a planning control, not permission to publish or change WordPress.

## Authority order

1. Direct user instruction and recorded human approval.
2. Approved WA-01 through WA-04 scope, architecture, design, and closeout records.
3. Tracked page source and content masters in this repository.
4. Tracked asset registers and approved asset-control records.
5. Evidence supplied by an owner or authorised external partner, recorded with date and scope.
6. Clearly labelled evidence dependencies requiring verification.

An item is not authoritative merely because it exists in a draft, preview, old
page, generated image, external service, or another repository.

## Conflicts and approvals

When sources conflict, stop the affected claim, record the conflict, and use the
authority order above. Do not silently merge incompatible wording. Legal,
financial, medical, safety, performance, availability, ownership, partnership,
or personal claims require the relevant human owner and, where appropriate,
professional review. Record owner, date, status, evidence, and next review.

## Other repositories and systems

Content from Platform Core, NEOS, GAIA, the Command Centre, Local AI Runtime,
or any other repository requires an evidence dependency and explicit public-use
approval. This repository does not prove technical behaviour by inference. The
private Command Dashboard and authenticated operational systems must not be
described as public website features without separate approval.

## External partners

External links are not integrations. A partner-provided description, image,
logo, URL, or status must identify its provider, permitted use, date, and review
state. Do not imply ownership, endorsement, formal partnership, shared
governance, API access, account sharing, or availability without evidence.

## Record requirements

Every controlled content item needs a named owner, evidence class, status, last
review date, and source or dependency. Claims must distinguish fact, history,
vision, principle, research, concept, prototype, development, availability,
and uncertainty.

## Non-negotiable rules

- Never invent functionality, partnerships, results, readiness, users, or availability.
- Never expose credentials, private paths, personal data, or internal controls.
- Never turn a concept, intention, or research question into a factual outcome.
- Never use internal planning labels as public copy.
- Escalate uncertainty instead of filling gaps with plausible wording.
