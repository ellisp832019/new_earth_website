## Architecture Amendment

The full ecosystem may be represented publicly at a high architectural level.

Internal capabilities such as:

- Company Control
- Local AI Runtime
- Knowledge / Librarian
- MCP / governed tools
- infrastructure/runtime capability

may be named and shown where useful to explain the whole ecosystem.

They must be labelled appropriately as internal capability/context.

Public representation must NOT expose:

- credentials
- secrets
- IP addresses
- private endpoints
- network topology
- databases
- private dashboards
- internal permissions
- detailed runtime topology
- security configuration
- unpublished implementation detail

Their inclusion does NOT imply:

- production readiness
- commercial availability
- completed integration
- canonical ownership
- autonomous authority

Where unresolved, ownership and detailed relationship remain:

AWAITING BASELINE

## Publishing / Automation Boundary

The site remains:

AUTOMATION-CAPABLE

not yet:

AUTOMATION-READY

Governed publishing remains:

CANONICAL SOURCE
→ PUBLICATION CANDIDATE
→ TOOL / AI ASSISTED PREPARATION
→ RULE / PRIVACY / CLAIM CHECKS
→ HUMAN REVIEW
→ APPROVAL
→ WEBSITE RECORD
→ BUILD
→ STAGING / PREVIEW
→ FINAL APPROVAL
→ PUBLISH
→ VERIFY
→ RECEIPT

Automation prepares.

Human authority publishes unless explicit future governance permits otherwise.
