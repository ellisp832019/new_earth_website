# Page Template and Content Model

## Status

WA-02A planning model, 2026-08-26. No final page copy, wireframes, theme
changes, WordPress templates, or implementation are included.

## Template families

- Gateway: Home and Start Here orientation.
- Doctrine hub: Blueprint, Vision, and Manifesto-style explanations.
- Pillar: index plus twelve consistent pillar pages.
- Ecosystem hub: public ecosystem map and safe system explainers.
- Project directory and project detail: status, owner, audience, evidence, and
  next action.
- Journal index and Journal article.
- About, founder story, people/team, and creator lane.
- Participation: Get Involved, collaboration, and contact.
- Research index and research paper.
- Resource/FAQ and glossary.
- Legal/policy.
- Progress/transparency.
- Protected-system boundary placeholder: explanatory public page only, never an
  authenticated application template.

## Reusable blocks and sections

- Accessible page title and context.
- Standard hero.
- Breadcrumbs and local navigation.
- Intro/why-this-matters.
- Blueprint relationship.
- Status/truth label.
- Evidence and review metadata.
- Project summary card.
- Related content.
- FAQ/accordion with keyboard support.
- Call to action.
- Contact pathway.
- Legal disclosure.
- Footer trust links.

## Standard hero model

Every hero requires:

- One clear page title.
- Short purpose statement, not final copy at this stage.
- One primary next action.
- Optional supporting visual with confirmed rights, licence, and attribution.
- Alt text or equivalent accessible description.
- No unverified claim, private screenshot, credential, or operational data.

## Truth and status label

Use only: LIVE, VALIDATED, IN DEVELOPMENT, PROTOTYPE, RESEARCH, PLANNED, FUTURE.
Labels must be visible where a project, system, research item, or future
capability could otherwise be misunderstood. Include owner, evidence date, and
review state when applicable. Use the most conservative supported label.

## Project summary card

A card must provide:

- Name and purpose.
- Blueprint relationship.
- Audience.
- Current status label.
- Owner.
- Evidence or last-reviewed date.
- Safe next action.
- Link to the canonical detail page only when active.

## Pillar page structure

Each pillar page includes:

1. Pillar name and orientation.
2. Relationship to the Blueprint.
3. Core questions or domains.
4. Practical implications.
5. Related projects and Journal items.
6. Previous/next pillar navigation.
7. Review and accessibility metadata.

## Journal/article structure

Journal index includes purpose, categories, search/filter scope, featured or
recent entries, and a clear Journal identity. Each article includes title,
author, publication date, updated date, content type, categories, tags, summary,
body, related pillar/project links, accessibility metadata, and next action.
Articles is not a second content type or index; it redirects to Journal.

## Founder and creator lanes

Founder's Journey is a shared narrative with shared approval. Team describes
roles and responsibilities. Peter Practical Guides and Hayley Conscious Living
remain distinct creator lanes with named ownership and consent. No content is
published in Hayley's name without her approval.

## Legal template

Legal pages require title, effective date, owner, jurisdiction/company fields
only when verified, review date, contact route, related policy links, and
accessible headings. Future product sales, refund, privacy, cookie, terms,
disclaimer, accessibility, and company disclosures require professional review.

## Contact and collaboration template

Provide purpose, audience, safe contact pathway, privacy notice, expected
response framing, and alternative route. Forms are not activated by this model.

## Progress/transparency component

Show status label, dated evidence, owner, last review, source link where safe,
change summary, and next review date. Avoid unsupported metrics or claims.

## Accessibility requirements

Target WCAG 2.2 AA. Templates require semantic landmarks, heading hierarchy,
keyboard operation, visible focus, contrast, reduced-motion consideration,
accessible names, alt text, captions/transcripts where relevant, responsive
behavior, and manual assistive-technology testing.

## Implementation boundary

This model is an IA input only. It does not authorize final copy, WordPress
implementation, plugin changes, theme changes, media publication, or deployment.
