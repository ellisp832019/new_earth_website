# Website V2 - Minimum Public Replacement Baseline

## Status

Current working-lane control, 2026-08-31. This document defines the minimum
capability baseline required before Website V2 can replace the current
New-Earth.UK WordPress site. It does not authorise deployment or live-site
changes.

## Required before controlled live cutover

- Accepted core narrative pages with approved public wording.
- Usable desktop and mobile layouts with accessible navigation.
- Public-safe launch imagery with rights, provenance, captions and alt text
  resolved.
- MicroGrow public coverage with evidence and publication gates closed.
- About and Get Involved pages.
- Contact route with tested delivery.
- Legal, privacy and disclaimer information.
- Journal landing and legacy-content route continuity.
- Legacy URL redirects and a reviewed route map.
- SEO essentials: metadata, sitemap, robots, canonical URLs, social metadata,
  favicon and a custom 404.
- Public-build leakage checks with no credentials, private paths or protected
  operational details.
- Staged deployment and a tested rollback capability.

## Not required for first launch

The following are not prerequisites for the minimum replacement baseline:

- Every future project page.
- NEOS, GAIA or Platform Core detail pages.
- Detailed pages for all 12 Pillars.
- A complete CMS.
- The full creator or product system.
- Every future programme or protected application.

## Governing boundary

The public website is the canonical source for public New Earth explanation.
Protected applications, private controls and specialist system ownership remain
separate. A project may remain local-preview-only while the replacement
baseline is completed. No public-enabled flag is implied by this control.

## Launch sequence

1. Public asset release pass.
2. MicroGrow publication closure.
3. Contact V1.
4. Legal, privacy and company-information closure.
5. Journal and legacy-content route coverage.
6. Legacy URL and redirect map.
7. SEO, sitemap, robots, canonical, social metadata and 404 closure.
8. Whole-site public release acceptance.
9. IONOS staging.
10. Controlled live cutover.
